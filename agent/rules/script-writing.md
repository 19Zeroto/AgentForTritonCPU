# 脚本编写规则

编写、修改或提供执行脚本时，必须保证脚本与调用者的当前工作目录和具体用户环境无关。
脚本需要作为长期 Agent 能力保存或迁移时，同时遵守 `skill-authoring.md` 的归类、
目录、统一入口和验证流程。

## 执行路径

- 不得假设脚本一定从仓库根目录或某个固定目录启动。
- 需要进入目标目录时，优先根据脚本自身位置解析路径，并在子 Shell/子进程中执行：

  ```bash
  SCRIPT_DIR="$(cd -- "$(dirname -- "${BASH_SOURCE[0]}")" && pwd)"
  (
    cd "${SCRIPT_DIR}/.." || exit 1
    ./run-command.sh
  )
  ```

- 如果必须在当前 Shell 中 `cd`，必须保存并恢复进入脚本前的路径；不得让脚本改变调用者后续命令的工作目录。
- Python 或其他语言调用外部命令时，应显式传入基于脚本位置解析的 `cwd`，不要依赖进程当前目录。
- 子线程共享进程的当前目录，不得在线程中通过 `os.chdir` 实现路径隔离；应使用显式路径，或将需要切换目录的工作放入带 `cwd` 的子进程。
- 路径含空格或特殊字符时，必须正确引用；Shell 路径默认使用双引号。

## 入口用法与设计说明

- 主要调用入口脚本必须在文件开头（shebang 或解释器声明之后）用简短注释或 docstring 标明最基础用法：调用方式、必需参数/环境变量和最小示例。
- 入口说明只描述怎么使用，不在脚本中堆放设计理念、架构决策或完整实现方案。
- 设计理念、设计方案、参数选择和流程说明必须放在独立的 Markdown 文档中；入口脚本注明该文档路径或链接，便于后续 review 和维护。

示例：

```bash
#!/usr/bin/env bash
# 用法：bash <脚本路径> --config <配置文件>
# 示例：bash <repo>/scripts/run.sh --config "$HOME/config.yaml"
# 设计说明：<skill>/references/workflow.md
```

## 环境路径

- 环境路径、缓存路径和工具链路径优先通过命令行参数或环境变量传入，并提供通用默认值，例如 `$HOME/...`；Python 使用 `Path.home()`。
- 禁止写死 `/home/<具体用户>/...` 或 `/home/user/...` 等用户绝对路径。这会绑定特定机器和用户，降低脚本通用性。
- 仓库路径应通过脚本位置、参数或环境变量解析；不得把当前目录下的 `./...` 当作唯一有效路径。
- 文档中的命令也必须遵守上述要求。示例可使用 `$HOME`、`~` 或占位符，不得出现真实用户的 `/home/...` 路径。

## 产物与临时文件

- 脚本生成的日志、缓存、结果文件、构建产物和其他中间文件必须保存到代码仓库外部；不得默认写入仓库内。
- 产物目录应通过命令行参数或环境变量指定，并提供仓库外的默认目录，例如 `~/agent/cache/...`。
- 创建产物目录遇到权限问题时，应尝试使用 `/tmp` 下的专用临时目录；不得因权限失败而回退到代码仓库或当前目录。
- 产物路径必须在执行前创建并检查可写性；脚本结束后按需要清理临时文件，并在输出中说明保留的产物位置。
